# 推理后端实现：第 8 步——服务管理与可观测性

## 1. 本步目标

前面的服务已经能够通过 TensorFlow 和 TensorRT 执行推理，但运维系统和 Web 页面还无法直接知道：服务是否可用、哪些模型加载成功、以及可选的模型名称。

本步增加两个只读管理接口，并让 Web 控制台根据服务端返回的实际模型列表动态初始化。

## 2. 新增的管理接口

路由由 `src/api/ManagementController.h` 和 `src/api/ManagementController.cc` 实现，并在 `src/http/main.cc` 中接入 HTTP 服务。两个接口都只允许 `GET`；其他方法返回 HTTP 405、JSON 错误体和 `Allow: GET` 响应头。

### 2.1 `GET /healthz`

该接口根据模型注册中心的当前状态生成健康摘要：

```json
{
  "status": "healthy",
  "serving": true,
  "backends": {
    "configured": 2,
    "available": 2,
    "healthy": 2
  }
}
```

状态语义如下：

- `healthy`：至少一个后端健康，且所有已配置后端均健康。
- `degraded`：服务仍可接受推理，但部分已配置后端不可用或不健康。
- `unavailable`：没有任何健康后端，返回 HTTP 503；前两种状态返回 HTTP 200。

`configured` 是注册项总数，`available` 是成功初始化的后端数，`healthy` 则进一步调用后端的 `healthy()` 状态。

### 2.2 `GET /v1/models`

模型目录接口返回默认模型和每个已配置后端的公开元数据：

```json
{
  "default_model": "yolov8n",
  "models": [
    {
      "name": "yolov8n",
      "version": "trt-10.0.1-fp16",
      "backend": "tensorrt",
      "priority": 100,
      "available": true,
      "healthy": true
    }
  ]
}
```

接口故意不返回模型文件的本地路径，避免将服务器目录结构暴露给客户端。同一个模型可以出现多次，分别代表 TensorRT 和 TensorFlow 实现；优先级与第 6 步的 `auto` 路由一致。

## 3. 注册中心状态统计

`ModelRegistry` 新增了：

- `availableBackendCount()`：统计初始化成功且持有后端实例的注册项。
- `healthyBackendCount()`：在可用基础上统计 `healthy()` 返回真的后端。

管理接口与推理路由共享同一个 `ModelRegistry`，因此不会出现“页面宣称有模型，调度器却找不到”的两套状态。仅启用 Mock 的构建也会创建注册中心，使管理接口始终可用。

## 4. 启动日志

注册中心初始化后，服务会输出每个注册项的模型名、版本、后端和加载状态。例如：

```text
Model yolov8n version=trt-10.0.1-fp16 backend=tensorrt status=ready
Model yolov8n version=tf-2.18.0 backend=tensorflow status=ready
```

如果后端加载失败，日志会记录 `status=unavailable` 和具体的失败原因，方便排查依赖库、模型文件或 GPU 环境问题。

## 5. Web 控制台的动态初始化

`root/index4.html` 不再将模型名称写死为文本输入框，而是在页面加载时并行请求 `/healthz` 和 `/v1/models`：

1. 健康接口用于在页面顶部显示当前的服务状态。
2. 模型目录会筛选健康注册项，按模型名去重后填充下拉框。
3. 如果服务端提供的 `default_model` 存在，页面会自动选中它。

后端选择仍保留 `auto`、`tensorflow` 和 `tensorrt`，因为它表示对同一模型的路由策略，而不是另一个模型名。

## 6. 测试与验证

`src/http/test/ManagementApiTest.cc` 使用一个健康假后端和一个不可用注册项，验证：

- 部分后端故障时返回 `degraded` 和 HTTP 200。
- 三类后端计数正确。
- 模型目录包含版本、后端、优先级和健康状态。
- 响应不包含本地模型路径。
- 非 `GET` 请求返回 405。

完整启用 TensorFlow 和 TensorRT 的联合构建共执行 8 个测试，全部通过。真实启动服务后，`/healthz` 显示 2 个后端均健康，`/v1/models` 同时返回 TensorRT FP16 和 TensorFlow SavedModel 版本。

## 7. 当前边界

本步是服务管理的最小可用基础，目前还有以下边界：

- `healthy()` 反映后端当前内部状态，还没有定时执行主动推理探测。
- 尚未提供 Prometheus 指标，也没有请求量、错误率和延迟直方图。
- 管理接口尚未配置认证与访问控制，不应在不可信网络上直接暴露。
- 模型注册表在启动时加载，尚不支持热更新或运行时卸载。
